# ContextIQ: технический отчёт

Дата выполнения: 22 октября 2026 г. Все значения ниже получены при фактическом запуске скриптов и тестов в Windows с Python 3.14.7. Исходные подробные результаты: [physics_metrics.json](physics_metrics.json), [ai_metrics.json](ai_metrics.json), [test_results.json](test_results.json), [api_smoke.json](api_smoke.json).

## 1. Постановка задачи

Реализовать Python-микросервис интеллектуального навигатора по контенту и активностям под настроение пользователя. Сервис принимает русский текст и эмодзи, оценивает настроение и интересы, ранжирует предоставленный каталог. Независимый физический модуль измеряет акустические признаки WAV и позволяет провести воспроизводимый эксперимент с известными синусоидальными сигналами. C# backend, React и PostgreSQL в текущую реализацию не входят.

## 2. Физические основы

Звуковой сигнал после АЦП представлен дискретной последовательностью. Частота дискретизации определяет временной шаг и верхнюю границу спектра по Найквисту `fs/2`. Длительность наблюдения определяет частотный шаг FFT. Амплитуда в цифровом файле измеряется относительно полного масштаба FS, без калибровки не переводится в Па.

RMS характеризует среднеквадратичную амплитуду, пик — максимальный модуль отсчёта. FFT показывает частотный состав всей записи. Окно Hann уменьшает утечку спектра ценой расширения спектрального пика. STFT показывает изменение спектра во времени. Центроид — среднее частот с весами по амплитудному спектру; он чувствителен к шумам и гармоникам. Максимум FFT у голоса не обязательно совпадает с частотой основного тона. Из этих признаков не делаются выводы об эмоциях.

## 3. Математическая модель

Для отсчётов `q[n]` signed PCM разрядности `b`: `x[n]=q[n]/2^(b-1)`. Для unsigned PCM8: `x[n]=(q[n]-128)/128`. В SciPy PCM24 хранится в старших разрядах int32; делитель — `2^31`. Stereo переводится в mono как `(L+R)/2` в float64, что исключает переполнение. Противофазные каналы могут взаимно подавляться.

```text
t[n] = n / fs,                  T = N / fs
RMS = sqrt((1/N) * sum(x[n]^2))
Peak = max(abs(x[n]))
x_sine[n] = A*sin(2*pi*f0*n/fs), RMS_theory = A/sqrt(2)
y[n] = x[n] - mean(x)
w[n] = 0.5 - 0.5*cos(2*pi*n/N)   (N >= 3)
X[k] = sum(y[n]*w[n]*exp(-2*pi*i*k*n/N))
a[k] = c[k]*abs(X[k])/sum(w)     (c=2, кроме DC и Найквиста, где c=1)
f[k] = k*fs/N,                  deltaF = fs/N
f_dominant = f[argmax(a[k])]     (DC исключён)
C = sum(f[k]*a[k])/sum(a[k])
Z[m,k] = sum(x[n+mH]*w[n]*exp(-2*pi*i*k*n/L))
delta_f_abs = abs(f_measured - f0)
delta_f_rel = delta_f_abs / f0
```

RMS/Peak вычисляются до удаления DC. Для 1–2 отсчётов FFT использует прямоугольное окно. При переменной составляющей ≤ `1e-12 FS` тональные показатели равны 0 по принятой договорённости; RMS постоянного ненулевого сигнала при этом ненулевой.

STFT: окно Hann, `L=max(2,min(1024,N))`, перекрытие `L//2`, шаг `H=L-L//2`, нормировка `scaling='spectrum'`, граничное дополнение нулями. Для N=1 сначала добавляется один ноль. Односторонние амплитуды преобразуются в `20*log10(max(a,1e-6))` dBFS, минимальное значение −120 dBFS. Спектрограммы не являются оценками спектральной плотности мощности в FS²/Гц. Подробная обработка WAV соответствует [документации SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.io.wavfile.read.html), STFT — [описанию SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.stft.html), частотная сетка — [определению DFT](https://numpy.org/doc/stable/reference/routines.fft.html).

## 4. Архитектура

FastAPI предоставляет `/health`, `/internal/analyze`, `/internal/audio-features`, `/internal/rank`. Pydantic проверяет входы и выходы, сериализация использует camelCase. Ошибочные данные возвращают 422; превышение размера WAV — 413; ошибка внешнего провайдера — 502. DSP выполняется в пуле потоков, чтобы не блокировать async event loop. Приняты пределы WAV: 20 MiB, 120 с, mono/stereo, integer PCM 8/16/24/32, little-endian RIFF, частота до 192000 Гц.

Текстовый анализ имеет независимые реализации: локальные детерминированные правила и необязательный OpenAI Responses API со Structured Outputs/Pydantic. Ключ читается из окружения, `.env` исключён из Git. Модель задаётся переменной `OPENAI_MODEL`, по умолчанию `gpt-4o-mini`. В отсутствие ключа `auto` выбирает demo. Ошибка настроенного OpenAI не маскируется под demo. Встроенная библиотека клиента использует подход из [official OpenAI documentation](https://developers.openai.com/api/docs/guides/structured-outputs).

Рекомендатель — чистая функция над переданными данными. Формула:

`S = 0.4*moodMatch + 0.3*preferenceMatch + 0.2*contextMatch + 0.1*novelty`.

`moodMatch` — совпадение настроения с ручной разметкой кандидата (0/1). `preferenceMatch` — среднее совпадения категории и доли желаемых тегов, пустые предпочтения дают 0.5. `contextMatch` — среднее близости энергии `1-|Eu-Ei|` и доли тем пользователя в тегах; без тем используется 0.5 для этой части. `novelty=1` для ID вне переданного `seenIds`, иначе 0. Все компоненты в [0,1]. Итог округляется до 8 знаков, при равенстве используется лексикографический порядок ID. Каталог содержит 32 объекта четырёх категорий; вымышленных URL и заявлений о реальных мероприятиях нет.

## 5. Методология физического эксперимента

Скрипт [run_experiment.py](../scripts/run_experiment.py) генерирует 10 сигналов: частоты 440 и 880 Гц, амплитуды 0.1, 0.25, 0.5, 0.75, 1.0 FS. Каждая запись: 16000 отсчётов/с, 2 с, 32000 отсчётов. Сигналы записываются в PCM16 по `round(32767*A*sin(...))`, затем читаются тем же декодером, что используется API. Таким образом измеряется и путь WAV, а не только исходный массив float.

Теоретический RMS для сравнения равен `A/sqrt(2)`. Кодирование через 32767 и декодирование через 32768 создаёт небольшое систематическое уменьшение амплитуды; добавляется ошибка округления. Допуски: ошибка частоты ≤5 Гц, абсолютная ошибка RMS ≤0.00005 FS. Графики формы сигнала показывают первые 30 мс, спектрограммы — всю запись. Частотные оси рисунков ограничены 4 кГц для читаемости, численные показатели рассчитаны по всему спектру до Найквиста.

В `data/audio/` ищутся реальные WAV. Они обрабатываются отдельно, не считаются синтетическими и не получают выдуманную эталонную частоту. Происхождение и голосовое содержимое пользовательских файлов автоматическим алгоритмом не подтверждаются.

## 8. Экспериментальная оценка текста

Использованы 25 русских фраз, по 5 предварительно размеченных примеров каждого настроения. Это небольшая демонстрационная выборка, требующая ручной проверки разметки. Она создавалась вместе с правилами и **не является полноценной научной валидацией** или независимым тестовым набором. По результатам измерений алгоритм после оценки не подгонялся.

Выполнено `scripts/evaluate_ai.py --mode demo`. Accuracy = `correct/N`; для класса `F1=2*TP/(2*TP+FP+FN)`, Macro-F1 — среднее F1 пяти классов; нулевой знаменатель трактуется как 0. Матрица: строки — эталоны, столбцы — ответы.

| Метрика | Фактически измеренное значение |
|---|---:|
| Верных ответов | 23 из 25 |
| Accuracy | 0.92 |
| Macro-F1 | 0.9222222222 |
| Среднее время вызова | 0.177088 мс |

Измерялся последовательный прямой вызов анализатора вместе с валидацией Pydantic, без HTTP, один проход без прогрева. Первый вызов включает компиляцию регулярных выражений. Единичный медленный первый вызов может поднять среднее выше p95 на выборке из 25 элементов. Время зависит от машины и нагрузки, эти значения не являются результатом нагрузочного теста.

Причины: отсутствие явного словарного маркера в первой фразе и ирония во второй. `confidence` правил — показатель силы правил, не калиброванная вероятность. Сетевой режим OpenAI в этой работе не запускался; наличие/доступность ключа не требовались.

## 10. План интеграции с ASP.NET Core

1. На backend создать DTO по OpenAPI: camelCase и enum строками, использовать HttpClientFactory.
2. Отправлять UTF-8 JSON на analyze/rank; WAV — как MultipartFormDataContent с именем `file`. Обрабатывать 413/422/502 и таймауты.
3. Хранить каталог и историю просмотров в PostgreSQL; backend передаёт актуальные кандидаты и `seenIds`.
4. Настроить внутреннюю авторизацию и ограничения тела запроса на стороне gateway/backend перед сетевым развёртыванием.
5. Добавить React UI, независимую разметку русских фраз, реальные записи с известными условиями съёмки, эксперимент с доступным OpenAI и нагрузочные измерения.
